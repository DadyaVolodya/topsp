# Концепция TopSP

Интеллектуальный слой программного продукта, объединяющий системные постановки, исходный код и само приложение в единый контекст. Используя этот контекст, он отслеживает изменения требований, понимает их смысл, определяет влияние на существующую реализацию и превращает изменения в конкретные действия для команды - от объяснения затронутых компонентов до формирования готовой задачи разработчику. Также TopSP позволяет обращаться к продукту на естественном языке, получать ответы с опорой на требования и код и переходить к связанному функционалу в интерфейсе.

## Демо-продукт

Сейчас в контексте только **Spring PetClinic** (Owner / Pet / Visit): `demo/sp` + `demo/code/petclinic-*`.

## Как храним СП и видим изменения

1. Текст СП попадает в `meet.specs.dir`.
2. Версии в `data/spec-versions/{documentId}/`.
3. Diff секций > impact по индексу кода > draft задачи.
4. В чат перед LLM всегда кладётся `PRODUCT CARD` (преамбула), чтобы модель не «уплывала».
